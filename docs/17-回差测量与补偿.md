# 任务02 · 舵机回差测量与补偿尝试

> 日期：2026-11-23
> 目的：解释阶跃稳态误差 2.7° 的来源，并尝试补偿

---

## 一、问题

闭环稳态误差稳定在 **2.7°**，加积分也消不掉：

| ki | 稳态误差 | 抖动峰峰 |
|---|---|---|
| 0.05 | 2.7° | 0.07° |
| 0.15 | 3.5° | 8.2°（振荡） |
| 0.30 | 3.5° | 8.0°（振荡） |

按计算，误差 2.7° 时控制器输出应有 16° 的舵机偏置，远大于任何死区。
所以必须确认：**是舵机不响应，还是机械在打滑。**

---

## 二、可重复性测试（开环定量）

停掉闭环，直接用 `P,1500,<us>` 给固定脉宽，每次停 1.5 秒再读角度：

| 脉宽 | 第一次 | 第二次 | 一致性 |
|---|---|---|---|
| 1300 µs | −0.28° | −0.26° | ✅ 差 0.02° |
| **1500 µs** | **+0.05°** | **+2.51°** | ❌ **差 2.46°** |
| 1700 µs | +9.21° | +9.01° | ✅ 差 0.20° |

**关键观察**：

```
从下往上走到 1500 µs → 0.05°
从上往下走到 1500 µs → 2.51°
```

同一个指令，因为"从哪个方向来"不同，差了 **2.46°**。

这就是**齿轮回差（backlash）**：SG90 是塑料齿轮，齿与齿之间有间隙。
换向时，前 2.5° 的转动只是让齿轮"贴上"，不传递力矩。

---

## 三、回差对闭环的影响

这解释了稳态误差，而且解释了为什么加积分没用：

```
控制器发现误差 2.7° → 命令舵机转 16°
舵机实际只转了 (16 - 2.5) = 13.5°，其中 2.5° 是"贴齿"空程
平台跟着动了约 13.5° … 但方向反转时又要吃掉 2.5°
→ 在死区/回差带附近来回，误差永远消不掉
```

---

## 四、补偿尝试（失败，但有价值）

### 实现思路

在 `module::Servo` 里检测方向反转，反转瞬间额外跳过一个回差量：

```cpp
const int8_t dir = (diff > 0.0f) ? 1 : -1;
if (backlash_ > 0.0f && last_dir_ != 0 && dir != last_dir_) {
  angle_ += (dir > 0) ? backlash_ : -backlash_;   // 先贴齿
  write_angle(angle_);
}
last_dir_ = dir;
```

### 实测结果

| 配置 | 稳态 | 误差 | 峰峰 |
|---|---|---|---|
| 无补偿（L,0） | 6.04° | 3.96° | **8.29°** |
| 有补偿（L,250，2.5°） | 4.78° | 5.22° | 8.86° |

**补偿后误差反而变大、抖动加剧。**

### 为什么失败

闭环控制里，误差在零附近时会**持续小幅换向**（每次几十毫秒就反向一次）。
每次换向都跳 2.5°，等效于给系统注入了一个 2.5° 的方波扰动。
这个扰动比原来的误差还大，系统被自己的补偿推得来回晃。

> **结论**：简单"换向跳变"式回差补偿，只适用于**单方向运动**的场合
> （比如机械臂定点抓取）。对闭环稳定控制，它会变成噪声源。

---

## 五、正确的解法：机械预紧（待实施）

软件补不了，就从机械上消除回差——这是更根本的办法。

### 原理

```
    无预紧：齿轮间隙让负载可以在两个齿面之间"晃" 2.5°
    
    加预紧：用皮筋给轴施加一个方向恒定的力
           → 齿轮始终贴在同一侧齿面
           → 间隙被"吃掉"，回差消失
```

### 做法

```
拿一根橡皮筋（配件包里就有）

一端勾在"上层平台"的前端
另一端勾在"底座"的后方

方向：让皮筋把平台往"低头"方向拉（或统一往抬头方向）
力度：刚好能拉平，不要太大（太大会让舵机持续出力发热）
```

### 预期效果

| 项 | 现在 | 加预紧后（预期） |
|---|---|---|
| 回差 | 2.5° | ≈ 0° |
| 阶跃稳态误差 | 2.7–4° | 有望 < 1° |
| 静态抖动 | 0.08° | 可能略增（皮筋有弹性）需实测 |

## 六、这一节的工程价值

任务02 的进阶项要求：

> 至少一种串级或前馈（角度环+角速度环，**或舵机死区/回差/负载力矩补偿**）

这次虽然没有实现成功的回差补偿，但**测量方法和失败分析本身就是交付内容**：

1. **测出了回差的确切数值**（2.46°），方法是"同指令、双向逼近"
2. **证明了简单补偿在闭环里会失效**，并解释了机理（换向频率远高于回差建立时间）
3. **给出了正确的解法方向**（机械预紧），而不是继续在软件里绕

这比"贴一段补偿代码然后宣称解决了"更有工程价值——
**知道一个方法为什么不行，和知道哪个方法行，同样重要。**
