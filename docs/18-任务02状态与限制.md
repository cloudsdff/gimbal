## 二、没做到的：大角度跟踪

### 现象

```
目标 +8° → 实际 0.15°（几乎不动）
目标 −8° → 实际 0.04°
```

静态很稳，但**目标变化时平台不跟随**。

### 已知的机械限制（实测）

| 项 | 实测值 | 影响 |
|---|---|---|
| **舵机→平台的传动比** | 舵机转 72°，平台转 26°（≈36%） | 控制权限只有 36%，要转 8° 需要舵机转 22° |
| **齿轮回差** | 2.46°（同一脉宽双向逼近差） | 死区带内控制失效 |
| **重力不对称** | 下行误差 0.43°，上行误差 4.84° | 上行需要额外力矩 |

### 试过的办法与结果

| 办法 | 结果 |
|---|---|
| 提高 kp（6 → 10 → 18） | 静态抖动从 0.1° 恶化到 3.6–4.2° |
| 提高 ki（0.05 → 0.3） | 出现 ±8° 极限环 |
| 软件回差补偿（换向跳 2.5°） | 误差反而从 3.96° 增到 5.22°，因为闭环换向频率太高 |
| 皮筋机械预紧 | 回差 2.46° → 1.17°，但静态变差、上行更吃力 |
| 重力前馈 ff_pitch | 已实现，未完成整定 |

### 本次找到并修掉的真 bug

**角速度符号与角度符号不一致**：

```
姿态模块内部对倒装模块做了 flip（gy 取反）
app 里却直接用 raw.gy 算角速度
→ 角度和角速度符号相反
→ 阻尼项变成正反馈
→ 表现："怎么调方向都振荡 / 跑飞"，浪费了大量时间
```

修法：`Attitude::corrected_rates()` 暴露修正后的角速度，控制器只用这个值。

修完后静态从"振荡"变成 0.06°/0.29°——**证明这个 bug 确实是主因**。
但跟踪问题在修完后仍未解决，说明还有机械或增益整定的工作要做。
