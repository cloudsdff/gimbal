# 任务02 · 蓝牙链路联调记录

> 日期：2026-11-23
> 结论：**蓝牙指令控制云台指向已验证通过**
> 关键发现：手上的"HC-05"其实是 **BLE 模块**，波特率 **38400**，命令走 **FFE2** 特征

---

## 一、模块不是 HC-05

买到的是标注"HC-05 带底板"的模块，但配对上电脑后，Windows 设备树里的证据很清楚：

```
设备节点：BTHLE\DEV_2F12CA722C54           ← BTHLE（低功耗蓝牙），不是 BTHENUM（经典蓝牙）
服务 UUID：0000FFE0-0000-1000-8000-00805F9B34FB  ← HM-10 / CC2541 的透传服务
特征：    0000FFE1（notify + write）
          0000FFE2（write only）
```

| | 真正的 HC-05 | 手上的模块 |
|---|---|---|
| 蓝牙协议 | 经典蓝牙 BR/EDR（SPP） | **BLE 4.0（GATT）** |
| Windows 表现 | 生成 COM 口 | **没有 COM 口**，只有 GATT 服务 |
| 命令通道 | 串口直接透传 | 写 **FFE2** 特征 |
| 回传通道 | 串口直接透传 | 订阅 **FFE1** 的 notify |

**对固件没有任何影响**：两边都是"UART 透传"，接线和指令格式完全一样。
差别只在**上位机侧**——PC 不能用 COM 口，得用 BLE 客户端（手机 APP 或 Python `bleak`）。

> **教训**：模块丝印和商家标题都不可信。判断依据要看**系统设备树里的协议类型**，
> 而不是看商品名。这个差别决定了上位机要怎么连，不看清楚会白折腾半天。

---

## 二、波特率是 38400（不是 9600）

一开始按"HC-05 出厂 9600"设置，收到的全是乱码：

```
环形缓冲实际内容： 00 00 00 ... 50 54 1C 3C 00 3C 00 3C 1C 1C 1C E0 ...
```

这些 `0x00` 和 `1C 3C` 是**帧错误**的典型表现——波特率不匹配时，接收端把噪声采样成了字节。

### 扫描过程

| USART2 波特率 | 8 字节探针收到的字节数 | 内容 |
|---|---|---|
| 4800 | +1 | 全 0 |
| 9600 | +2 | 全 0 |
| 19200 | 0 | — |
| **38400** | **+8** | **`ABCXYZ\r\n` 正确** ✅ |
| 57600 | 0 | — |
| 115200 | +15 | 乱码 |

**38400 刚好收到 8 字节且内容完全正确**，就是它。

> **教训**：串口不通时不要只试 9600/115200。
> 判断方法不是"有没有收到字节"，而是**收到的字节数是否等于发出的字节数、内容是否正确**。
> 只有数量对、内容对，才是真通了。

## 三、命令要写 FFE2，不是 FFE1

模块有两个可写特征，文档里没写区别：

| 特征 | 属性 | 实际作用 |
|---|---|---|
| FFE1 | `notify, write` | 主要用于**模块 → 手机**（notify） |
| **FFE2** | `write` | **手机 → 模块**（透传到串口）✅ |

一开始写 FFE1 且用 `response=False`（无响应写），MCU 一个字节都收不到。

改成 **FFE2 + `response=True`（带响应写）** 之后立刻通了：

```
bt 计数：14 → 16 → 31 → 67 → 80   （逐次递增）
```

> **教训**：BLE 的 `write-without-response` 不是所有模块都正确实现。
> 遇到"写了没反应"，先换成带响应写——它能保证数据真的送达对端。

## 四、验证结果

### 4.1 单轴指令

```
发送：T,3000,0        （yaw = 30.00°, pitch = 0°）
读回：target_yaw   = 30.00°    ✅
      target_pitch = 0.00°     ✅
舵机：servo=1887 µs
```

**这个 1887 可以手算验证**：

```
角度误差 = 30 - 0 = 30°
rate_ref = kp × 30 = 2.0 × 30 = 60 °/s
e_rate   = 60 - 0 = 60
out      = kd × 60 = 0.6 × 60 = 36°  → 限幅到 35°
舵机角   = 90 + 35 = 125°
脉宽     = 500 + 125 × 11.11 = 1889 µs
实测 1887 µs，误差 2 µs（0.2°）✅
```

### 4.2 双轴指令（烧录后直接验证，无需手动设波特率）

```
发送：T,-4500,2000     （yaw = -45°, pitch = 20°）
读回：target_yaw   = -45.00°   ✅
      target_pitch =  20.00°   ✅
```

### 4.3 其他指令

| 指令 | 效果 | 验证 |
|---|---|---|
| `C` | 重新校准 | 日志出现 `cmd recalibrate` ✅ |
| `B,<baud>` | 在线改蓝牙波特率 | `cmd bt baud -> 38400 : Ok` ✅ |
| `K,<milli>` | 改滤波系数 alpha | `cmd alpha -> 950/1000` ✅ |

## 五、接线（最终确认）

| 模块引脚 | 蓝药丸 | 说明 |
|---|---|---|
| VCC | **5V** | 模块板载 LDO，3.3V 带不动 |
| GND | GND | 必须共地 |
| **TXD** | **PA3** | 模块发 → MCU 收 |
| **RXD** | **PA2** | MCU 发 → 模块收 |

供电注意：板子用 USB 供电时 5V 引脚才有电；此时 **J-Link 的 3V3 必须拔掉**（两个电源不能顶在一起）。

## 六、上位机侧怎么连（三种方式）

### 方式 1：手机 APP（最简单）

装 **Serial Bluetooth Terminal**（Android）或 **nRF Connect**：

```
① 配对 HC-05，密码 1234
② 用 BLE 模式连接（不是经典蓝牙）
③ 发送时勾选"加回车换行"
④ 发 T,3000,0
```

### 方式 2：Python bleak（本工程验证用的方式）

```python
import asyncio
from bleak import BleakClient, BleakScanner

async def main():
    dev = await BleakScanner.find_device_by_name("HC-05", timeout=15)
    async with BleakClient(dev) as cli:
        for s in cli.services:
            for c in s.characteristics:
                if c.uuid.lower().startswith("0000ffe2"):
                    await cli.write_gatt_char(c, b"T,3000,0\r\n", response=True)
asyncio.run(main())
```

### 方式 3：调试串口（CH340，最稳）

蓝牙只是"无线替代方案"，调试阶段直接用 CH340 发指令更可靠：

```
COM3 @ 115200（CH340）
发：T,3000,0
```

## 七、调试手段：不依赖串口也能看到板子状态

当串口不可用（比如 CH340 没插）时，用 J-Link 直接读内存变量：

| 变量 | 地址（本次构建） | 含义 |
|---|---|---|
| `target_yaw` / `target_pitch` | `0x20003814` | 云台目标（float） |
| 蓝牙接收计数 | `0x20003A78` | 累计收到的字节数 |
| 环形缓冲 head/tail | `0x20003A7C` / `0x20003A80` | head==tail 表示全部被读走 |
| 环形缓冲内容 | `0x20003A84` | 原始字节，能直接看出收到什么 |

**用途**：判断"数据到没到"（看计数）、"程序读没读"（看 head/tail）、"内容对不对"（看缓冲）。
这次定位波特率问题就是靠读原始字节——`0x00` 和 `0x1C 0x3C` 直接暴露了帧错误。

> 地址每次重新编译会变，要用 `arm-none-eabi-nm` 重新查符号。

## 八、排查表（下次遇到类似问题照这个走）

| 现象 | 最可能原因 | 怎么确认 |
|---|---|---|
| 收不到任何字节 | TXD/RXD 接反或没接 | 读 PA3 电平：空闲应为高 |
| 收到字节但全是 `0x00` | 波特率不匹配 | 扫波特率，看数量是否等于发送字节数 |
| 收到正确字节但不执行 | 指令没以 `\n`/`\r` 结尾 | 看缓冲内容末尾有没有 `0D 0A` |
| BLE 写了没反应 | 写错特征 / 用了无响应写 | 改 FFE2 + `response=True` |
| 连不上 | 手机还连着模块 | 断开手机，模块只能连一个中心设备 |
| 计数不增长但连接正常 | 模块串口波特率和 USART2 不一致 | 用 `B,<baud>` 逐个试 |
